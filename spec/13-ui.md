# 13 — UI: views, layout and styling

**Status:** `spec`. This document is Vela's replacement for SwiftUI, UIKit,
Jetpack Compose, HTML and CSS.

---

## 1. Why a styling language at all

CSS is a document format that grew a layout engine. Its problems are structural,
not cosmetic:

| CSS problem | Vela's answer |
| --- | --- |
| Global namespace, specificity wars | every style is a typed value with a name; composition is explicit; there is no cascade and no specificity |
| Typos fail silently | a property that does not exist is a compile error; a value of the wrong unit is a compile error |
| Layout is emergent | one layout model, declared on the container, expressed in five properties |
| Responsive design is string-ish | `@when` is a real condition over the container's width |
| States are bolted on (`:hover`) | states are values a style declares it handles |
| Accessibility is an afterthought | a11y fields are on the element and required for interactive nodes in strict mode |
| Reuse means a class-name convention | reuse is composition: `.style(Base)` then override |
| Animation is CSS keyframes in another file | animation is a style member, typed, with reduced-motion handled |
| The platform is a browser | the same style compiles to DOM+CSS on web and to real UIKit/AppKit attributes on Apple |

That is the whole argument. Vela does not "also have styling" — styling is part
of the type system.

## 2. Views

A view is a function from properties to elements. It is a declaration, not a
class.

```vela
view Card(title: Str, @children: List<Element> = []) {
  column(style: CardStyle) {
    text(title).style(.heading)
    children
  }
}
```

* `view Name(props) { body }` declares a component.
* Props are typed fields; a prop marked `@children` collects the element children
  written at the use site.
* The body is an **expression** that produces one element (or a list of them).
* Using a view is calling it: `Card(title: "Hello") { text("body") }`.
* A view with no props is used bare: `Divider()`.
* Views are values; they may be passed, stored and returned. Rendering happens in
  the framework, not by calling the view.

### 2.1 The application root

```vela
#[app]
view Root() {
  Nav {
    page(Home())
  }
}
```

`#[app]` marks the single root view of an `app`-profile package. Exactly one per
program (`E-UI-010`).

## 3. Elements

An element is a node in the view tree. It is created by a builder function named
after the element, takes structural properties positionally or by name, and every
element returns `Element`, so they can be nested, collected and conditionally
produced.

### 3.1 Layout containers (8)

| Element | Meaning |
| --- | --- |
| `row(...)` | children in a horizontal line |
| `column(...)` | children in a vertical line |
| `grid(...)` | children placed on a row/column grid |
| `zstack(...)` | children overlaid, last on top |
| `scroll(...)` | a scrollable viewport with one child |
| `spacer()` | flexible space in a row or column |
| `canvas(...)` | immediate-mode 2D painting surface |
| `group(...)` | no layout of its own; groups children for a shared style |

### 3.2 Content (9)

| Element | Meaning |
| --- | --- |
| `text(Str)` | a run of text |
| `richText(...)` | text with inline spans (`bold`, `link`, `code`) |
| `image(source, alt: Str)` | an image from an asset, a path or bytes |
| `icon(name)` | a vector icon from the icon set |
| `field(value, onChange: Func(Str) -> Void)` | text input |
| `toggle(isOn, onChange: Func(Bool) -> Void)` | a switch |
| `slider(value, min, max, onChange)` | a range control |
| `select(value, options, onChange)` | a choice control |
| `divider()` | a rule |

### 3.3 Interactive (7)

| Element | Meaning |
| --- | --- |
| `button(label, onTap: Func(...) -> Void)` | a button |
| `link(label, href)` | navigation |
| `menu(...)` / `menuItem(...)` | a popup menu |
| `sheet(isPresented, onDismiss) { }` | a modal sheet |
| `dialog(...)` | a modal alert |
| `dropZone(...)` | drag and drop target |
| `gestureArea(...)` | a region that handles gestures without paint |

### 3.4 Structural (5)

| Element | Meaning |
| --- | --- |
| `when(cond) { }` | conditionally include children |
| `each(items) { |item| ... }` | keyed list rendering |
| `select_` / `matchView` | render one of several branches |
| `portal(...)` | render into another part of the tree (overlays, toolbars) |
| `fragment(...)` | a list of elements with no wrapper node |

An unknown element name is `E-UI-020` with a spelling suggestion.

### 3.5 Elements are not strings

There is no way to write raw HTML here. The tree is data, and each backend
renders it: UIKit views on iOS, AppKit on macOS, DOM nodes on web, a
`vela-gfx` draw list on `sys`.

## 4. State, bindings and the environment

Four member kinds inside a `view`, plus `computed`:

```vela
view Counter(start: Int = 0) {
  state count: Int = start          # owned, mutable, survives re-render
  bind query: Str                   # two-way, from a parent
  env theme: Theme                  # provided above, read here
  computed doubled: Int = count * 2 # derived, recomputed when a dependency changes

  column(gap: 8dp) {
    text("${count} / ${doubled}")
    button("+1", onTap: { count += 1 })
  }
}
```

| Kind | Written | Semantics |
| --- | --- | --- |
| `state` | `state x: T = init` | per-instance mutable value; writing schedules a re-render of this view |
| `bind` | `bind x: T` | two-way binding to a parent's `state` |
| `env` | `env x: T` | read from the nearest provider; `env x: T = default` supplies a fallback |
| `computed` | `computed x = expr` | pure derivation, memoised until a dependency changes |

Rules:

* Writing a `state` or a bound field from an event handler is the only way to
  change a view. There is no direct mutation of the tree (`E-UI-030`).
* Re-render granularity is the **view**: a `state` write re-evaluates that view's
  body, and children re-render only if their props changed (structural sharing on
  `Element`).
* `state` inside `each` is per item; the item's key is its identity (`E-UI-031`
  if the collection is not keyed).
* Values passed to children are captured at render time; there is no implicit
  two-way binding except through `bind`.

### 4.1 Effect hooks

```vela
view Clock() {
  state now: Instant = time.now()

  onTick(every: 1s) { now = time.now() }
  onAppear { log.info("mounted") }
  onDisappear { log.info("unmounted") }
  onKey(.escape) { dismiss() }

  text(time.format(now, "HH:mm:ss"))
}
```

`onTick`, `onAppear`, `onDisappear`, `onKey`, `onResize`, `onFocusChange` are
declared like members and cleaned up automatically when the view unmounts.

## 5. The layout model

One model, five properties, no floats.

Every container is a **one-dimensional flow with wrapping** (`row`, `column`) or
a **two-dimensional grid** (`grid`), overlaid by `zstack`. There is no `float`,
no `inline` text flow inside a box, and no margin collapsing.

| Property | Values | Where it goes |
| --- | --- | --- |
| `dir` | `row`, `column`, `rowReverse`, `columnReverse` | container |
| `wrap` | `nowrap`, `wrap`, `wrapReverse` | container |
| `gap` | `8dp`, `(row: 4dp, column: 8dp)` | container |
| `align` | `start`, `center`, `end`, `stretch`, `baseline` | container (cross axis) |
| `justify` | `start`, `center`, `end`, `between`, `around`, `evenly` | container (main axis) |
| `weight` | `1`, `2.5` | child (flex growth; `0` by default) |
| `size` | `100dp`, `fill`, `hug`, `(w: 50%, h: 100dp)` | child |

```vela
row(align: .center, justify: .between, gap: 12dp, pad: 16dp) {
  text("Acme").style(.title)
  spacer()
  button("Sign in", onTap: signIn).weight(0)
  image(avatar, alt: "user").size(32dp).radius(16dp)
}
```

### 5.1 Sizing rules

* `hug` (default): the element takes what its content needs.
* `fill`: the element takes the space its parent offers.
* `100dp`, `50%`, `auto`: an explicit size.
* `weight(n)` distributes **leftover** space after gaps and fixed children.
* A child may not exceed its parent's constraints; overflow is clipped unless
  `overflow: visible`, which is a style property, not a layout accident.

### 5.2 Grid

```vela
grid(columns: 3, gap: 12dp) {
  card("A")
  card("B")
  card("C").span(2)          # take two cells
}
```

`columns` may be `3`, `(1fr, 2fr)`, or `repeat(autoFill, min: 200dp)`.

### 5.3 Text layout

`text` wraps at word boundaries by default, honours `width`, and reports its
intrinsic size for `hug` parents. `whiteSpace: nowrap` is opt-in. Line breaking
follows the Unicode line-breaking algorithm, not a fixed-width character count,
so a proportional font produces correct breaks.

## 6. Units

| Unit | Written | Meaning |
| --- | --- | --- |
| density-independent | `16dp` | 16 pt on Apple, 16 CSS px on web — one number, same visual size |
| pixel-exact | `16px` | a physical pixel; for hairlines |
| relative to font | `1.5em` | multiple of the current font size |
| root relative | `1.5rem` | multiple of the theme's base font size |
| percentage | `50%` | of the parent's size on the same axis |
| fraction | `1fr` | share of remaining space (grid, flex) |
| viewport | `100vw`, `100vh` | of the window (macOS, web) |
| character | `40ch` | width of `0` in the current font |
| angle | `45deg`, `0.5turn` | transforms, gradients |
| time | `150ms`, `0.2s` | animation |
| colour | `#RRGGBB`, `#RRGGBBAA`, `rgb(...)`, `hsl(...)`, `token.x` | paint |

Numeric units are **distinct types**: `Length`, `Percent`, `Fraction`, `Angle`,
`Duration`. `pad: 16` is `E-UI-040` ("expected a Length, found Int"), and the
hint names the fix. This is the single most valuable check in the whole system,
because `margin: 10px` vs `margin: 10` is a typo class CSS cannot see.

## 7. Colours

```vela
let brand: Color = #3B82F6
let subtle = brand.withAlpha(0.4)
let text = Color.mix(#000, #fff, 0.8)
let surface = token.surface            # from the active theme
```

* Colours are values of type `Color`, in sRGB by default; `P3(...)` and
  `oklch(...)` are available and converted per platform.
* Light and dark are one style with two values, not two stylesheets:
  `background: (light: #fff, dark: #111)`.
* Contrast is checkable: `color.contrast(fg, bg)` returns a WCAG ratio, and
  `assertContrast(.AA)` on a style is a compile-time check in `strict` builds
  (`E-UI-050`) — the first time a design system can fail CI.

## 8. Where styling lives

A style is a **declaration**, not a class name and not an inline string.

```vela
style CardStyle {
  background: token.surface
  radius: 12dp
  pad: 16dp
  border: 1dp solid token.outline
  shadow: 0 2dp 8dp #0002
}
```

and it is applied by name:

```vela
column(style: CardStyle) { ... }
text("hi").style(.heading)
button("Go").style(CardStyle).override(pad: 24dp)
```

Rules:

* `style Name { ... }` declares a reusable style. Its properties are checked
  against the table in §9.
* `.style(X)` applies one style; `.stack(X, Y)` applies two, later winning.
* `.override(p: v)` applies an anonymous single-property override. This is
  where CSS would have had a specificity contest; here it is local and explicit,
  and **an override of a property the base style does not have is a compile
  error** (`E-UI-060`) rather than a silent misspelling.
* A style may `extend` another: `style PrimaryButton extends BaseButton { ... }`.
* There is no global selector, no descendant combinator, no `!important`, and no
  way for one style to affect an element that did not name it.

### 8.1 Element modifiers — the complete chain

Every element returns an `Element`, and these are the only calls that may follow
one. Each is checked by the same rule as a style property: unknown name
`E-UI-020`, wrong type `E-UI-040`, not applicable `E-UI-061`.

| Modifier | Meaning |
| --- | --- |
| `.style(S)` / `.stack(S, T, …)` | apply styles, later winning |
| `.override(prop: value, …)` | one-off property overrides, checked against the base style |
| `.size(...)`, `.weight(n)`, `.span(n)` | layout, same values as the properties in §9 |
| `.label(Str)`, `.hint(Str)`, `.role(Role)`, `.focusOrder(Int)`, `.live(Region)` | accessibility (§13) |
| `.disabled(Bool)` | disables interaction and sets the `.disabled` state |
| `.invalid(Bool)` | sets the `.invalid` state and announces the invalid value |
| `.haptic(Haptic)` | a haptic on tap (`app` only; a warning elsewhere) |
| `.onKey(Key, fn)` / `.onKey(Key) { }` | a key handler on a focusable element |
| `.onHover(fn)` / `.onFocus(fn)` | additional handlers beyond `when` states |
| `.each(item)` / `.key(k)` | identity for a dynamic element |

A modifier applied to an element that cannot support it — `.span` on a `text`,
`.haptic` in a `web` build, `.onKey` on a non-focusable node — is
`E-UI-061`/`E-UI-070` rather than a silent no-op, because a silently ignored
platform request is how a UI ends up working on one platform only.

### 8.2 Local functions in a view

A `view` body may declare local functions with `fn name(...) { }`, exactly like
any block (doc 05 §3). They close over the view's `state`, `bind`, `env` and
`computed` members and are the idiomatic way to keep an event handler readable:

```vela
view Editor() {
  state text: Str = ""

  fn persist() {
    try fs.writeStr(draftPath(), text) catch e { log.error("${e.message()}") }
  }

  onDisappear { persist() }

  field(text, onChange: |v| { text = v }).label("Draft")
}
```

A local function may be passed to a child view as a `Func(...)`, which is how a
parent hands an action down without exposing its state.

## 10. Themes and tokens

```vela
theme Light {
  token.surface    = #FFFFFF
  token.surfaceAlt = #F3F4F6
  token.onSurface  = #111827
  token.brand      = #3B82F6
  token.danger     = #DC2626
  token.radius     = 12dp
  token.space      = (xs: 4dp, sm: 8dp, md: 16dp, lg: 24dp)
  token.font       = font("Inter", size: 16dp)
  token.baseFont   = 16dp
  token.breakpoints = (sm: 640dp, md: 768dp, lg: 1024dp)
}

theme Dark extends Light {
  token.surface    = #111827
  token.onSurface  = #F9FAFB
}

#[app]
view Root() {
  theme(follow: .system, light: Light, dark: Dark) {
    page(Home())
  }
}
```

Rules:

* A token is a typed constant; `token.surface` in a style resolves against the
  active theme at render time, so switching themes re-renders without rebuilding
  styles.
* A theme may be provided at any depth; the nearest provider wins — this is the
  only cascade in the language, and it is one level deep and explicit.
* A style that uses a token not declared by any theme in scope is `E-UI-080`.
* `theme(follow: .system, ...)` reacts to the OS appearance change; `appearance`
  on an element is the escape hatch for one subtree.

## 11. States and queries

### 11.1 States

```vela
style ButtonStyle {
  background: token.brand
  pad: (y: 10dp, x: 16dp)
  radius: token.radius

  when .hover   { background: token.brand.lighten(0.1) }
  when .pressed { background: token.brand.darken(0.1) }
  when .focused { focusRing: 2dp }
  when .disabled { opacity: 0.5 }
  when .selected { border: 2dp solid token.onSurface }
}
```

Available states: `.hover`, `.pressed`, `.focused`, `.focusVisible`,
`.disabled`, `.selected`, `.checked`, `.dragging`, `.dropping`, `.loading`,
`.invalid`, `.stale`. A state the framework cannot observe on the target
platform is dropped with `W-UI-020` (there is no hover on a phone), so a style is
portable by construction rather than by checking.

### 11.2 Container queries

```vela
style CardStyle {
  pad: 16dp

  @when self.width < 400dp { pad: 12dp }
  @when self.width >= 900dp { pad: 24dp }
}
```

`self.width`, `self.height` refer to the element's own resolved size; `window.width`
refers to the frame. There is no need for breakpoint classes, and no "the layout
broke at 700px" class of bug, because the query measures the container, not the
viewport.

### 11.3 Platform conditions

```vela
style ToolbarStyle {
  @when target == .ios { pad: (y: 8dp, x: 12dp) }
  @when target == .macos { pad: (y: 6dp, x: 10dp) }
  @when target == .web { pad: (y: 8dp, x: 14dp) }
}
```

`@when` conditions are evaluated at compile time for `target` and at render time
for size, motion and appearance.

## 12. Animation

Animation is a style member. There is no second file and no keyframe language to
learn.

```vela
style CardStyle {
  transition: background, transform
  transitionDuration: 150ms
  transitionCurve: ease.out
  transitionDelay: 0ms
}

style FadeIn {
  anim enter(duration: 300ms, curve: spring(stiffness: 180, damping: 18)) {
    from { opacity: 0; translateY: 8dp }
    to   { opacity: 1; translateY: 0dp }
  }
}

style Spinner {
  keyframes spin {
    0%   { rotate: 0deg }
    100% { rotate: 360deg }
  }
  anim infinite(loopSpin, duration: 1s, curve: linear)
}
```

Rules:

* `transition: p, q` animates those properties when they change between renders;
  a property not listed changes instantly.
* `anim` names an animation, its duration and its curve; `from`/`to` or
  `keyframes` define it.
* Curves: `linear`, `ease.in`, `ease.out`, `ease.inOut`, `spring(...)`,
  `cubicBezier(x1, y1, x2, y2)`, `steps(n)`.
* `reduceMotion: follow` (the default) collapses every transition and animation
  to an instant change when the user has reduced motion on. A style that must
  keep motion says `reduceMotion: always`, and the build reports every such style
  (`W-UI-030`), which is how accessibility reviews become tractable.
* Animation is driven by the host's frame callback (a display link on Apple,
  `requestAnimationFrame` on web), never by a sleeping thread.
* Interrupting an animation resumes from the current value, not from the start.

## 13. Accessibility

Not a separate annotation pass — fields on the element, checked with the style.

```vela
button("", onTap: close) {
  icon("xmark")
}
  .label("Close")             # required: an icon button with no text
  .hint("Closes this panel")
  .role(.button)
  .focusOrder(1)

image(logo, alt: "")          # decorative: empty alt is explicit
heading("Settings", level: 1)
```

* `label` is required for an interactive element with no text content
  (`E-UI-090` in `strict` mode, a warning in `loose`).
* `image` requires `alt`, which may be `""` for decorative images.
* `heading(level:)` produces a `text` with `role` and `heading` set.
* Focus order follows reading order unless `focusOrder` says otherwise.
* `liveRegion` marks a region that screen readers announce when it changes.
* A `dialog` traps focus and returns it on dismiss, always; a `sheet` does the
  same. This is implemented in the framework, not in a style.
* Touch targets below 44dp are `W-UI-040` with the offending element; `hitSlop`
  is the fix that does not disturb the layout.

## 14. Assets

```vela
asset logo: Image = "logo.png"                  # assets/logo.png
asset hero: Image = "hero.jpg"
asset inter: Font = "Inter-Variable.ttf"

#[app]
view Root() {
  image(hero, alt: "mountains").size((w: 100%, h: 240dp))
  text("Acme").font(inter, weight: 700, size: 32dp)
}
```

* An `asset` declaration names a file under `assets/` (doc 08 §11) and gives it a
  type, so an image can never be used where a font is expected.
* Resolution variants are automatic: `logo@2x.png` and `logo@3x.png` beside
  `logo.png` are picked by density; web emits `srcset`.
* Formats accepted: PNG, JPEG, SVG, WebP; a vector asset is rasterised per density
  on Apple and emitted as inline SVG on web.
* Fonts are bundled and subset per weight actually used; unused weights are
  dropped, and the build reports the size saved.
* A missing asset is a compile error (`E-UI-100`), not a broken image at runtime.

### 14.1 Assets chosen at runtime

A name that comes from data — a product's picture, a user's avatar — cannot be an
`asset` declaration, so there is one dynamic form:

```vela
impl Product {
  fn picture(self) -> Image { assets.load(self.imageName) }
}
```

`assets.load(name: Str) -> Image` resolves the name against the asset manifest
emitted by the build. It is a lookup in a generated table, not a file read, and a
name that is not in the manifest panics with `E-UI-100` naming the missing file —
the same failure the static form gives, at the moment the value is used rather
than at compile time. `vela check --lint` lists every `assets.load` call site,
because it is the one place where an asset reference is not checked statically.

## 15. Navigation

```vela
#[app]
view Root() {
  Nav {
    route(.home) { Home() }
    route(.detail(id: Int)) { Detail(id) }
    route(.settings) { Settings() }
  }
}

view Home() {
  button("Open 42", onTap: { nav.push(.detail(id: 42)) })
}
```

* `nav.push`, `nav.pop`, `nav.replace`, `nav.reset` are the whole API.
* Routes are an `enum`, so a destination's parameters are typed and a missing one
  is a compile error.
* The stack is state: restoring it on app relaunch is `state.serialize(nav)` and
  one line in the app root.
* Web maps `nav` onto history and URLs (doc 14 §4), so the same navigation code
  produces back-button behaviour and deep links.

## 16. Gestures and input

```vela
gestureArea(onTap: { ... }, onLongPress: { ... })
zoom(onScale: |s| { scale = s }, min: 0.5, max: 4.0)
drag(onMove: |delta| { offset += delta }, onEnd: snap)
swipe(.left) { archive() }
keyboard(.command) { onKey("s") { save() } }
```

Gestures compose by nesting; the innermost gesture that claims a press wins, and
`pointerEvents: none` lets presses pass through. A `gestureArea` without a
`label` is `E-UI-090`, because a gesture-only control is invisible to a screen
reader.

## 17. Canvas

Immediate-mode 2D drawing, for charts, signatures, games and anything a layout
cannot express.

```vela
canvas(width: fill, height: 200dp, redraw: data) {
  |c: Painter| {
    c.clear(token.surface)
    c.line((0dp, 100dp), (width, 100dp), color: token.outline, width: 1dp)
    for p in series {
      c.circle(x(p), y(p), 3dp, fill: token.brand)
    }
    c.path(points, stroke: token.brand, width: 2dp, curve: .smooth)
  }
}
```

`Painter` offers `clear`, `line`, `rect`, `circle`, `path`, `text`, `image`,
`clip`, `save`/`restore`, `transform`, `gradient`. It maps to Core Graphics on
Apple, Canvas2D on web, and a draw list on `sys`. `redraw:` names the values that
invalidate the surface.

## 19. Rendering model and performance

* The tree is immutable data. A render produces a new tree; the framework diffs
  it against the previous one and applies the minimal set of mutations.
* Diffing is keyed: `each(items, key: |x| x.id)` is O(n) and preserves element
  identity, so scroll position and focus survive a list update.
* A style is resolved once per changed element; identical styles are
  deduplicated, so 1,000 cards share one resolved style object.
* Layout is a single pass down and up (constraints, then sizes). No element may
  trigger a second layout pass: `E-UI-110` if a style reads its own resolved size
  in a way that would require one.
* Target: 16.6 ms per frame on a 2020 phone for a 500-element screen. `vela run
  --profile-ui` reports render time, diff size and allocation per frame.
* Off-screen work (image decode, network) is `async` and never blocks a frame;
  `E-UI-120` catches a blocking call in a view body.

```vela
#[test]

  assertEq(screen.find(byRole: .status).text(), "1 / 2")

#[test]
fn cardPadShrinks() {
```

## 21. CSS migration

Every CSS property in common use maps to one Vela property, one style declaration

## 23. A whole screen, styled

```vela
theme Light {
  token.surface   = #FFFFFF
  token.onSurface = #111827
  token.brand     = #3B82F6
  token.outline   = #E5E7EB
  token.danger    = #DC2626
  token.radius    = 12dp
  token.space     = (xs: 4dp, sm: 8dp, md: 16dp, lg: 24dp)
}

style CardStyle {
  background: token.surface
  radius: token.radius
  pad: token.space.md
  border: 1dp solid token.outline
  shadow: (x: 0dp, y: 2dp, blur: 8dp, color: #00000014)
  transition: background, border
  transitionDuration: 120ms

  @when self.width < 400dp { pad: token.space.sm }
  when .hover { background: token.surface.darken(0.02) }
}

style PriceStyle {
  foreground: token.danger
  fontWeight: 700
  fontSize: 20dp
}

view ProductCard(product: Product) {
  state expanded: Bool = false

  column(style: CardStyle, gap: token.space.sm) {
    row(align: .center, gap: token.space.sm) {
      image(product.image, alt: product.name)
        .size(48dp)
        .radius(8dp)
      text(product.name).fontSize(17dp).weight(1)
      text(money(product.price)).style(PriceStyle)
    }

    when(expanded) {
      text(product.description).lineClamp(6).foreground(#4B5563)
    }

    row(justify: .end, gap: token.space.sm) {
      button(if expanded { "Less" } else { "More" },
             onTap: { expanded = !expanded })
        .label(if expanded { "Show fewer details" } else { "Show more details" })
      button("Add to cart", onTap: { cart.add(product) })
        .style(PrimaryButton)
        .haptic(.light)
    }
  }
}
```

No stylesheet. No class names. No `!important`. No `.card:hover .card__price`,
no breakpoint ladder, no separate accessibility pass, and the same file produces
a UIKit screen on iOS, an AppKit window on macOS, and DOM nodes on the web.
