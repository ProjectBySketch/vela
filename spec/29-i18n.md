# 29 — Internationalisation and text

**Status:** `spec`. Module: `i18n` (unstable). Related: doc 13 §9.3 (typography),
doc 02 §3.1 (`Str`).

Text handling is a language-level concern in Vela because the UI language makes it
one: a view that hard-codes "3 items" is a bug in twelve languages at once. The
design rule: **every user-visible string is either a translation key or an
explicitly marked literal, and the compiler can tell you which.**

---

## 1. Message catalogues

```vela
// src/messages.vela
messages AppMessages {
  title = "Vela Store"
  cart(count: Int) = one "1 item" other "${count} items"
  greeting(name: Str) = "Hello, ${name}"
  price(amount: Money) = "${amount}"
  error.network = "Network unavailable. Try again."
}
```

* A `messages` declaration is the single source of truth for user-visible text.
  Its name is a namespace: `AppMessages::cart(3)`.
* Plural forms use the locale's own rules: `one`/`other` in English, `one`/`few`/
  `many`/`other` in Polish, `zero`/`one`/`two`/`few`/`many`/`other` in Arabic. The
  compiler checks that the forms required by every declared locale are present
  (`E-I18N-010`), because a missing Arabic plural is a bug nobody finds in review.
* `vela i18n extract` writes `locales/en.json` (or `.xliff`) from the declaration;
  `vela i18n import` reads translated files back; a key that exists in a
  catalogue but not in a locale file is `E-I18N-011` at build time for locales
  declared as required.
* Interpolation stays typed: `${count}` in a plural form is an `Int`, and a
  translator cannot change that.

---

## 2. Using messages

```vela
text(AppMessages::cart(store.count()))
```

* `messages` values are `Str`-like but carry the catalogue and the key, so a UI
  framework can react to a locale change without re-reading source.
* A ICU MessageFormat subset is supported for the cases plurals cannot express:
  `select(gender, male: "He", female: "She", other: "They")` and
  `number(amount, style: currency)` / `date(when, style: short)`. Anything outside
  the subset is `E-I18N-020` with the supported grammar in the message.
* A literal string in a UI position is allowed but flagged (`W-I18N-010`) unless
  it is marked: `raw("ACME")` — brand names, code, and test fixtures are the
  legitimate cases, and marking them makes the exception visible.

## 3. Locales and formatting

```vela
let locale = Locale.parse("de-DE")?
num.format(1234.5, locale: locale)          # 1.234,5
money.format(9.99, currency: .eur, locale: locale)   # 9,99 €
datetime.format(now, style: .medium, locale: locale) # 18.11.2026, 14:03:11
list.format(["a", "b", "c"], locale: locale)         # a, b und c
```

| Formatter | Respects |
| --- | --- |
| number | decimal separator, grouping, native digits (`arab`, `deva`), compact notation |
| currency | symbol position, spacing, fraction digits, accounting negative form |
| date/time | order, separators, 12/24-hour, first day of week, time-zone name |
| relative time | "3 days ago" with the locale's plural rules |
| list | conjunction and disjunction |
| unit | "5 km", "5 Kilometer", with the plural form |
| collation | sorting by the locale's rules (`str.compare(locale:)`) |

All of these are pure functions of a value, a locale and a style; no global state,
no implicit "current locale" that a test cannot set.

## 4. Text direction

```vela
view Screen(locale: Locale) {
  direction(locale.direction) {
    ...
  }
}
```

* Layout is logical: `start` and `end` replace `left` and `right` throughout doc
  13, so mirroring is automatic. A style that hard-codes `left`/`right` is
  `W-I18N-020` in a package that declares an RTL locale.
* Numbers, code, URLs and phone numbers are wrapped in `bidi.isolate(...)`
  automatically by the text renderer; a user-supplied string containing bidi
  control characters is stripped unless `allowBidi: true`, because that is how a
  filename or a username is made to look like something else.
* Icons with direction (arrows, chevrons) are declared as `mirrorInRtl: true`.

---

## 5. Input and identifiers

* `str.normalise(form: .nfc)` is available and applied to user input before
  storage when a package opts in; comparison of two `Str` is byte-wise unless
  `str.compare(locale:)` is used, and that distinction is documented because it is
  the one that bites.
* Case folding: `str.lower(locale:)` for Turkish dotted/dotless i, `str.upper`.
* Grapheme cluster boundaries follow UAX #29 in `Str.len` and indexing (doc 02
  §3.1).
* A `PersonName`, `Address` and `PhoneNumber` type live in `i18n` so that "first
  name, last name" is not baked into a schema as two columns for the whole world.

## 6. Translation workflow

```sh
vela i18n extract              # src/messages.vela -> locales/en.json
vela i18n status               # which keys are missing, per locale
vela i18n import de.json       # merge a translation back
vela i18n check                # CI: no missing keys, no unused keys, no raw strings
```

* Translations live in `locales/<tag>.json` (or `.xliff` for a translation
  agency), committed to the repository.
* `vela run --locale de-DE` renders the whole app in a locale, and
  `vela run --pseudo` renders pseudolocalised text (`Ĥéĺĺó`) with 40 % extra
  width, which is how a layout bug is found before a translator does.
* Screenshot tests (doc 13 §20) run per locale, so RTL and long German compounds
  are caught in CI.

---

## 7. Accessibility and text scaling

* `text` respects the platform's text scale; a layout that breaks at 200 % is a
  `W-UI-040`-adjacent finding, and `vela run --ui-audit --dynamic-type` reports
  clipped elements.
* Fonts are subset per script; a package that declares `ja` ships a CJK font, and
  the build reports the added bytes (doc 13 §14).

---

## 8. Diagnostics

| Code | Meaning |
| --- | --- |
| `E-I18N-010` | a required plural form is missing for a declared locale |
| `E-I18N-011` | a catalogue key has no translation in a required locale |
| `E-I18N-020` | unsupported MessageFormat construct |
| `E-I18N-030` | interpolation type mismatch between catalogue and call site |
| `W-I18N-010` | raw user-visible string not marked |
| `W-I18N-020` | physical `left`/`right` in an RTL package |
| `W-I18N-030` | unused translation key |
